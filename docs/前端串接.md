# 個人記帳系統前端 API 串接規範書

本文件為個人記帳系統（`ledger-api`）之手機端介面串接規格書。提供前端程式開發設計師在開發手機畫面時之資料傳輸協議、端點規格、驗證約束、錯誤代碼對照表與規格差異分析依據。

---

## 壹、共通規則

1. **固定三鍵外層封裝結構**
   所有 API 端點之 HTTP 回應主體（Response Body）一律為 JSON 物件，外層結構固定包含以下三個鍵：
   - `code`（整數）：與 HTTP 狀態碼完全一致（如 `200`、`201`、`400`、`404`、`500`）。前端可直接透過 `code` 判斷操作結果。
   - `message`（字串）：給使用者看的人話繁體中文訊息，說明業務執行結果或失敗原因。**絕對不含**底層資料庫表名、約束名、SQL 關鍵字或例外堆疊。
   - `data`（物件 / 陣列 / `null`）：實際承載之業務資料。
     - 成功查詢：回傳目標物件或陣列清單。
     - 成功新增：回傳寫入後之完整資料物件。
     - 操作失敗（`code >= 400`）：**固定為 `null`**。

2. **HTTP 狀態碼定義與行為**
   | 狀態碼 | 意義 | 適用情境 | `data` 內容 | 前端處理建議 |
   | :--- | :--- | :--- | :--- | :--- |
   | `200 OK` | 成功查詢或成功更新 | 取得單筆、取得清單（含空清單 `[]`）、更新資料、取得試算與彙總數值 | 物件、陣列或計算結果 | 渲染畫面或提示更新成功 |
   | `201 Created` | 成功建立新資源 | `POST` 新增記錄成功（如新增花費、入帳、帳戶等） | 寫入後包含系統產生欄位之完整物件 | 關閉表單彈窗並將新項目加入列表或導回列表頁 |
   | `400 Bad Request` | 客戶端請求錯誤或違反業務約束 | 缺少必填欄位、格式錯誤、名稱重複、金額小於等於 0、超額賣出等 | 固定為 `null` | 於表單或 Toast 提示 `message` 人話文字 |
   | `404 Not Found` | 找不到指定資源 | 存取或更新不存在的 `id` | 固定為 `null` | 提示「找不到指定資源」並導回首頁或列表頁 |
   | `500 Internal Server Error` | 伺服器內部錯誤 | 資料庫連線中斷、非預期後端異常 | 固定為 `null` | 提示「資料庫暫時連不上，請稍後再試」 |

3. **客戶端不送的欄位**
   前端在發送新增（`POST`）或更新（`PATCH`）請求時，以下欄位由伺服器與資料庫端管理，**一律不得傳送**（若前端不慎傳送，後端會直接忽略）：
   - `id`：資料列主鍵，由資料庫自動產生。
   - `created_at`：建立時間戳記，由伺服器自動寫入。
   - `updated_at`：更新時間戳記，由伺服器自動寫入。
   - 發票新增時：不送 `prize_status`（後端預設初始值為 `unchecked`）。
   - 交易新增時：不送 `voided_at`（作廢時間戳記僅能在呼叫作廢端點時由系統自動打上）。

4. **日期、時間與金額的型別規範**
   - **日期（Date）**：一律為 ISO 8601 之 `YYYY-MM-DD` 格式字串（例如：`"2026-08-15"`）。
   - **時間戳記（Timestamp）**：一律為帶有 UTC 時區之 ISO 8601 字串（例如：`"2026-08-15T08:30:00.000000+00:00"`），前端應轉換為手機端本地時區顯示。
   - **金額與數量（Amount / Quantity / Price / Balance）**：在 JSON 中一律為 **JSON 數字（number）**（如 `70.0`、`1000.0`、`10.0`），**嚴禁使用字串引號包裝**。
   - **匯率（FX Rate）**：折算新台幣匯率 `fx_rate_to_twd` 為數值型別（number，如 `1.0`、`32.5`）；計價幣別為 `TWD` 時固定傳送 `1.0`。

5. **可空欄位（Nullable）在回應中的表現**
   - 可空欄位（如備註 `note`、商家 `merchant`、隨機碼 `random_code` 等）在資料庫中無值時，回應 JSON 中一律明確輸出為 `null`（例如 `"note": null`），**不會從鍵名中移除**。前端可安心解構或依鍵名讀取。
   - 客戶端在發送請求時，傳入 `null` 與完全省略該鍵效果相同。

## 參、端點規範手冊

> **說明**：
> 1. 以下端點以 `./ledger-api/docs/交換格式.md` 已定義之規範為準。
> 2. 範例中的 `id` 一律以數字示範，**實際呼叫請以 API 回應之 `id` 為準**。
> 3. 回應外層固定包含 `code`、`message`、`data` 三個鍵。

### 1. 健康檢查 (Health Check)

#### (1) 基本服務健康檢查 `GET /api/health`
- **方法**：`GET`
- **路徑**：`/api/health`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：
  - `status`（字串）：服務狀態，正常為 `"ok"`。
  - `time`（字串）：伺服器目前 UTC 時間戳記。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "伺服器運作正常，測試正常可以進行其他任務。",
    "data": {
      "status": "ok",
      "time": "2026-11-14T07:30:00.000000+00:00"
    }
  }
  ```

#### (2) 資料庫連線檢查 `GET /api/health/db`
- **方法**：`GET`
- **路徑**：`/api/health/db`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：
  - `status`（字串）：連線狀態，正常為 `"ok"`。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "資料庫連線正常",
    "data": {
      "status": "ok"
    }
  }
  ```

### 2. 帳戶 (Accounts)

#### (1) 取得帳戶清單 `GET /api/accounts`
- **方法**：`GET`
- **路徑**：`/api/accounts`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：帳戶物件陣列，每個物件欄位如下：
  - `id`（整數）：帳戶識別碼。
  - `name`（字串）：帳戶名稱。
  - `kind`（字串）：帳戶種類（`cash`、`bank`、`credit_card`、`broker`）。
  - `currency`（字串）：計價幣別代碼（3 碼，如 `TWD`）。
  - `opening_balance`（數值）：期初餘額。
  - `statement_day`（整數 / 可空）：結帳日（1~31）。
  - `payment_day`（整數 / 可空）：繳款日（1~31）。
  - `created_at`（字串）：建立時間 (UTC)。
  - `updated_at`（字串）：更新時間 (UTC)。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "取得帳戶清單成功",
    "data": [
      {
        "id": 1,
        "name": "現金錢包",
        "kind": "cash",
        "currency": "TWD",
        "opening_balance": 0.0,
        "statement_day": null,
        "payment_day": null,
        "created_at": "2026-08-01T02:00:00.000000+00:00",
        "updated_at": "2026-08-01T02:00:00.000000+00:00"
      }
    ]
  }
  ```

#### (2) 新增帳戶 `POST /api/accounts`
- **方法**：`POST`
- **路徑**：`/api/accounts`
- **查詢參數**：無
- **請求欄位**：
  - `name`（字串，必填）：帳戶名稱（不可重複）。
  - `kind`（字串，必填）：帳戶種類（`cash`、`bank`、`credit_card`、`broker`）。
  - `currency`（字串，選填，預設 `"TWD"`）：幣別代碼（3 碼英文）。
  - `opening_balance`（數值，選填，預設 `0.0`）：期初餘額。
  - `statement_day`（整數，選填）：結帳日（1~31）。
  - `payment_day`（整數，選填）：繳款日（1~31）。
- **成功時 `data` 欄位**：完整帳戶物件。
- **最小 JSON 範例**：
  - **請求**：
    ```json
    {
      "name": "日常現金包",
      "kind": "cash"
    }
    ```
  - **回應 (`201 Created`)**：
    ```json
    {
      "code": 201,
      "message": "帳戶建立成功",
      "data": {
        "id": 1,
        "name": "日常現金包",
        "kind": "cash",
        "currency": "TWD",
        "opening_balance": 0.0,
        "statement_day": null,
        "payment_day": null,
        "created_at": "2026-08-01T02:00:00.000000+00:00",
        "updated_at": "2026-08-01T02:00:00.000000+00:00"
      }
    }
    ```

#### (3) 取得單一帳戶 `GET /api/accounts/<id>`
- **方法**：`GET`
- **路徑**：`/api/accounts/<id>`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：單一帳戶物件。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "取得帳戶成功",
    "data": {
      "id": 1,
      "name": "日常現金包",
      "kind": "cash",
      "currency": "TWD",
      "opening_balance": 0.0,
      "statement_day": null,
      "payment_day": null,
      "created_at": "2026-08-01T02:00:00.000000+00:00",
      "updated_at": "2026-08-01T02:00:00.000000+00:00"
    }
  }
  ```

#### (4) 修改帳戶 `PATCH /api/accounts/<id>`
- **方法**：`PATCH`
- **路徑**：`/api/accounts/<id>`
- **查詢參數**：無
- **請求欄位**（皆選填，僅傳送需修改的欄位）：
  - `name`（字串）：新帳戶名稱。
  - `statement_day`（整數 / `null`）：結帳日（1~31）。
  - `payment_day`（整數 / `null`）：繳款日（1~31）。
- **成功時 `data` 欄位**：更新後之完整帳戶物件。
- **最小 JSON 範例**：
  - **請求**：
    ```json
    {
      "name": "常用現金包"
    }
    ```
  - **回應 (`200 OK`)**：
    ```json
    {
      "code": 200,
      "message": "帳戶更新成功",
      "data": {
        "id": 1,
        "name": "常用現金包",
        "kind": "cash",
        "currency": "TWD",
        "opening_balance": 0.0,
        "statement_day": null,
        "payment_day": null,
        "created_at": "2026-08-01T02:00:00.000000+00:00",
        "updated_at": "2026-08-01T03:00:00.000000+00:00"
      }
    }
    ```

### 3. 帳戶餘額 (Account Balance)

#### (1) 取得帳戶即時餘額 `GET /api/accounts/<id>/balance`
- **方法**：`GET`
- **路徑**：`/api/accounts/<id>/balance`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：
  - `account_id`（整數）：帳戶識別碼。
  - `name`（字串）：帳戶名稱。
  - `currency`（字串）：帳戶幣別。
  - `opening_balance`（數值）：期初餘額。
  - `balance`（數值）：原幣別當前計算餘額。
  - `original_currency_balance`（數值）：原幣別餘額（同 `balance`）。
  - `twd_balance`（數值）：按記錄匯率折算後之新台幣餘額。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "取得帳戶餘額成功",
    "data": {
      "account_id": 1,
      "name": "常用現金包",
      "currency": "TWD",
      "opening_balance": 0.0,
      "balance": 200.0,
      "original_currency_balance": 200.0,
      "twd_balance": 200.0
    }
  }
  ```

- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 欄位**：移轉物件陣列。
- **最小 JSON 範例**：
  ```json
  {
    "code": 200,
    "message": "取得移轉清單成功",
    "data": [
  ```

  - `tax`（數值，選填，預設 `0.0`）：交易稅（$\ge 0$）。
  - `currency`（字串，選填，預設為標的幣別）：計價幣別。
  - `fx_rate_to_twd`（數值，外幣必填，台幣預設 `1.0`）：匯率。
  - `post_income`（布林值，選填）：若為 `cash_dividend` 或 `capital_reduction` 且為 `true`，會在資料庫同一交易事務建立對應的 `incomes`。
  - `income_category_id`（整數，當 `post_income=true` 時必填）：入帳分類 ID。
- **成功時 `data` 欄位**：建立後之交易物件。
